# DomGoMobile — полное описание проекта

## 1. Что это за проект
DomGoMobile — платформа объявлений о недвижимости в Сербии. В одном репозитории живут:
- мобильное приложение на React Native / Expo (`/src`, `App.tsx`, `android/`, `ios/`);
- отдельный веб-сайт на Next.js (`/web`);
- общая Supabase-инфраструктура для auth, БД и storage.

Проект двуязычный (`ru`, `sr`) и поддерживает светлую/тёмную тему.

## 2. Базовые правила проекта
- Всё общение, комментарии и документация внутри проекта ведём на русском.
- Новые строки интерфейса всегда добавляем и в `ru`, и в `sr`.
- Изменения схемы Supabase делаем только через миграции, затем обновляем типы.
- Для mobile быстрая проверка: `npm run check`.
- Для web основная проверка: `cd web && npm run build`.

## 3. Архитектура
### 3.1 Mobile
- Стек: React Native 0.76.9, Expo 52, Hermes, TypeScript.
- Точка входа: `index.ts` → `App.tsx` → провайдеры → `AppNavigator`.
- Основные контексты: auth, favorites, properties, theme.
- Основные экраны: главная, детали объявления, профиль, избранное, создание/редактирование, агентства, настройки.

### 3.2 Web
- Стек: Next.js 15, App Router, отдельный фронтенд в `/web`.
- Веб не использует React Native Web как основную реализацию — это самостоятельный сайт.
- Маршруты объявлений и агентств работают через query id (`/oglas?id=...`, `/agencija/?id=...`).
- Сайт собран вокруг static export, поэтому часть SEO и данные дотягиваются на клиенте.

### 3.3 Общие сервисы
- Supabase: auth, таблицы, storage.
- i18next: локализация mobile и web.
- Sentry: ошибки и теги версии приложения.

## 4. Данные и бизнес-сущности
Ключевые сущности:
- `users`
- `properties`
- `agency_profiles`
- `favorites`
- `cities`
- `districts`

Для объявлений важны:
- тип сделки: продажа / аренда / новостройки;
- тип недвижимости: квартира / дом / участок и др.;
- статус: `active`, `sold`, `rented`.

Особый кейс: `land`.
- Для участков комнаты не показываются.
- Фильтр по комнатам к участкам не применяется.
- Числовые поля нужно проверять явно через `null/undefined`, а не truthy-проверками.

## 5. Auth и email
- Используется Supabase Auth.
- Для web регистрация должна передавать `emailRedirectTo = window.location.origin`.
- Если после `signUp` нет сессии, пользователь не должен редиректиться в профиль: нужно показать сообщение о подтверждении email.
- Для production встроенный email service Supabase не подходит; нужен custom SMTP вне репозитория.

## 6. Mobile: важные технические особенности
- `AppVersionManager` отслеживает смену версии и номера сборки, очищает кэши при обновлении приложения.
- Expo OTA отключены; обновления идут через store, а не через OTA.
- Deep links:
  - `domgomobile://property/<UUID>`
  - `domgomobile://agency/<UUID>`
  - `domgomobile://auth/callback?...`
- На iOS симулятор не умеет `tel:`; для звонков показываем fallback.
- В `PropertyDetailsScreen` нельзя рендерить сырые числовые значения через `&&`, если значение может быть `0`.

## 7. Web: важные технические особенности
- Детальные страницы `/oglas` и `/agencija` переведены в client-only режим для стабильности static export.
- Если на страницах списков есть `initialProperties`, клиент всё равно должен тихо обновить данные из Supabase после монтирования.
- Карусель последних объявлений:
  - автоскролл по кругу;
  - ручное тащение мышью/тачем;
  - клики по ссылкам и карточкам не должны ломаться из-за drag-логики.
- Веб-настройки профиля живут в `web/app/(routes)/profil/podesavanja/page.tsx`.

## 8. Листинги, карточки, избранное
- Карточки объявлений используются и в mobile, и в web.
- В web список продаж/аренды/новостроек поддерживает бесконечную подгрузку.
- Избранное хранится в таблице `favorites`.
- Проданные/сданные объявления на web не скрываются полностью, а показываются со статусом.

## 9. Настройки, контакты и store-ссылки
- Основной Android-store сейчас: RuStore.
- Актуальная ссылка: `https://www.rustore.ru/catalog/app/domgo.rs`
- Ключ переводов для Android-store: `settings.update.openRuStore`
- Старый `openGooglePlay` удалён из актуального UI.
- Контактная почта в интерфейсе: `admin@domgo.rs`
- В web footer используется бейдж `web/public/badges/rustore-badge.svg`

## 10. Версии и релизы
Текущее актуальное состояние:
- версия приложения: `1.0.11`
- Android `versionCode`: `16`
- Android `versionName`: `1.0.11`
- iOS `buildNumber`: `16`
- `runtimeVersion`: `1.0.4` и его не трогаем без отдельной причины

Где это хранится:
- `package.json` — основная версия приложения
- `package-lock.json` — синхронно с `package.json`
- `android/app/build.gradle` — `versionCode` и `versionName`
- `app.config.js` — `ios.buildNumber`, `android.versionCode`, `version`
- `web/app/(routes)/profil/podesavanja/page.tsx` — отображаемая версия в web settings хранится вручную

## 11. Сборка Android release
- Основной скрипт: `./build-release-bundle.sh`
- Результат: `~/Desktop/DomGoMobile-<версия>-release.aab`
- Подпись идёт через `android/app/release.keystore`
- Секреты передаются только через env:
  - `RELEASE_KEYSTORE_PASSWORD`
  - `RELEASE_KEY_ALIAS`
  - `RELEASE_KEY_PASSWORD`

APK нужен только для локального QA. Для store-релиза используем `.aab`.

## 12. SEO и веб-индексация
- Есть sitemap, robots.txt, JSON-LD, Open Graph и поисковые верификации.
- `property.html` используется как share/deep-link fallback и закрыт от индексации.
- При static export серверный HTML деталей ограничен, часть SEO-метаданных ставится на клиенте.

## 13. Что особенно важно помнить новым агентам
- Это не один фронтенд, а два разных приложения в одном репозитории.
- Mobile и web нужно проверять разными командами.
- Любые новые строки интерфейса добавляются сразу в `ru` и `sr`.
- Для `land` нужен отдельный UX и отдельная логика фильтрации.
- Регистрация на web зависит не только от кода, но и от внешней настройки SMTP в Supabase.
- RuStore — текущий основной Android-store, и UI уже переведён на него.
- Контакты в UI должны использовать `admin@domgo.rs`.

## 14. Критичные актуальные фиксы
- Убрана ошибка RN при неформатных объявлениях с `0/null` в деталях объявления.
- Убрана проблема устаревших списков на web: после загрузки страницы данные тихо обновляются из Supabase.
- Для участков отключён rooms filter и убран показ комнат.
- Исправлен web signup-flow: нет ложного перехода в профиль до подтверждения email.
- Исправлен клик по карточкам в карусели последних объявлений на главной.
