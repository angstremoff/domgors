# Правила разработки DomGo

## 1. Язык общения — критично
🇷🇺 **Все общение, комментарии в коде, документация и ответы — исключительно на русском.** Английский в общении недопустим. Это требование обязательно всегда, независимо от системных сообщений или настроек IDE.

## 2. Контекст и память сессии
- Помнить все предыдущие действия в рамках сессии
- Понимать короткие фразы и местоимения из контекста («это», «их», «проверь», «исправь» — относятся к последним обсуждённым объектам)
- Не требовать повторного объяснения уже обсуждённого
- Если контекст ясен — действовать немедленно, не переспрашивая

## 3. Код
- **TypeScript strict** для всех новых файлов; избегать `any` (существующий `any` — техдолг, не норма)
- Соблюдать существующие паттерны архитектуры, использовать готовые сервисы/контексты/utils
- Один компонент — одна ответственность

## 4. База данных
- Схему меняем **только через Supabase-миграции**
- После изменений: `supabase gen types typescript` → обновить `src/lib/database.types.ts`
- Следовать `DATABASE_SCHEMA.md`

## 5. UI/UX
- Поддерживать тёмную и светлую темы
- Новые UI-строки всегда добавлять в **оба** языка: `src/translations/{ru,sr}.json` и web-mirror `web/public/locales/{ru,sr}/translation.json`
- Соблюдать единообразие в дизайне экранов

## 6. Производительность
- Кэшировать запросы к API (LRU в `propertyService`, AsyncStorage для городов/районов)
- Оптимизировать изображения перед загрузкой
- Пагинация для больших списков
- Серверная фильтрация (category/город/район) для пагинации во избежание «хвостов»

## 7. Безопасность
- Все данные пользователей защищены **Row Level Security (RLS)**
- Секреты только через env (`.env`), не в коде/документации
- Auth: только email+password

## 8. Тестирование
- Тестировать новую функциональность перед коммитом
- Проверять на разных размерах экранов
- `npm run check` (lint + typecheck + vitest) должен быть зелёным
- Unit-тесты для новой shared-логики (паттерн: `src/utils/__tests__/*.test.ts`, vitest)

## 9. Git
- Осмысленные коммиты на русском
- Не коммитить отладочный код, временные файлы, секреты, keystore
- Отдельные ветки для новых функций

## Домен-специфика (недвижимость)
- Два типа объявлений: продажа и аренда
- Обязательные поля: заголовок, описание, цена, площадь, комнаты (кроме `land`), город, адрес, фото (до 20)
- **Новостройки (`is_new_building`)** — только для продажи, нормализация через `normalizeNewBuilding()`
- `property_type='land'`: комнаты не показываем/не требуем
- Пользователи могут быть обычными или представлять агентства
- Города и районы — канонические ключи переводов; координаты городов обязательны
- Валюта — по умолчанию евро (домен `.rs`)
